# 0014: Design system rules come first in every layout

## Context
Layouts often start from an old reference: a past cover, a partner's template, a screenshot. The first weekly cover copied the September cover too closely: a large full-purple sphere and purple dates. Together with the logo, purple took far more than its share of the canvas, and the sphere outweighed the title. The reference set the look; the design system should have.

## Decision
1. **Rules first, no improvisation.** Every layout follows, in this order:
   1. the design system: [colors and typography](../wiki/brand/visual/colors-typography.md), [canvases and type scale](../wiki/brand/visual/canvases.md), [grid and spacing](../wiki/brand/visual/grid-spacing.md), [logo](../wiki/brand/visual/logo.md), [icons](../wiki/brand/visual/icons.md), [data visualization](../wiki/brand/visual/data-visualization.md);
   2. the layout approach: [art direction](../wiki/brand/visual/art-direction.md);
   3. the format page, if the format has one.
2. **A reference is input, not a spec.** An old layout, a supplied template or a "nice visual trick" only tells what the piece is about and what it should contain. Anything in it that breaks a rule is dropped or rebuilt to the rule, even if the reference looked good.
3. **Conflicts are named, not decided silently.** When a request or reference conflicts with a rule, the agent says which rule, proposes the version that follows it and builds that version. An exception exists only if the director approves it in chat and it is written on the format page with the reason.
4. **Check before showing.** Before a layout goes to the director, the agent checks it against the rules: palette and purple share, type roles and sizes, margins and grid, logo file and clear space. Deviations are listed, not hidden.

## Consequences
- `AGENTS.md` carries the rule for every agent.
- Format pages may add rules but never relax the design system without a recorded exception.
