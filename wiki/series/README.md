# Series

One folder per content series. Every series has a type ([decision 0008](../../decisions/0008-series-types.md)):

| Type | What it is | Example |
|---|---|---|
| `recurring` | A regular issue built from data; only the data changes | Development Update |
| `thematic` | One theme, every post written from scratch; `arc: true` when the order of posts matters | Würth × Iagon |
| `evergreen` | A set of reusable posts on rotation | Discord and YouTube invitations |

Articles are a format, not a type: they belong to a thematic series or stand alone. Posts outside any series live in [`wiki/posts/`](../posts/README.md).

## Registry

Generated by `scripts/series-registry.py` from each `series.md` and its posts ([decision 0009](../../decisions/0009-series-registry.md)). Don't edit the table by hand: change the series page, then run the script.

Before starting a new series, check the table: if a series already covers the same narrative and audience, the idea is an issue of that series. An `active` series that misses two of its cycles shows as **overdue** and is paused or finished at the quarterly review.

## Folder

- `series.md`: idea, goal, narrative, boundary, format, cadence, rules, and the sections required for its type. Start from `templates/series.md`.
- `posts/`: one file per post, from `templates/post.md`. Texts as published, links, results. File names by series type and no images: [decision 0012](../../decisions/0012-post-history.md).
- `learnings.md`: what worked, what didn't, what we change.
- `issue/`: fixed wording of an issue, one file per channel (recurring series).
- `inputs/`: the editorial input of each issue, one file per period.

Raw data goes to `raw/archive/`, visual templates to `layouts/`, build output to `dist/` (not in git). Full map: [decision 0011](../../decisions/0011-series-files.md).

The point is to keep the logic of each series, not just an archive of texts.
